# SL-ADMIN-PRODUCT-AUDIT-SNAPSHOT-20260520 Spec

## 基本信息

- Feature ID: `SL-ADMIN-PRODUCT-AUDIT-SNAPSHOT-20260520`
- Feature 名称: 商品审核历史快照
- 负责人: Codex
- 目标上线环境: staging / prod

## 背景

管理端商品审核页已经会提示审核员核对商品关键字段，但当前只展示实时商品字段，缺少审核当时的字段快照。商品被审核后如果卖家继续修改名称、规格、价格、仓储或描述，平台无法还原当时审核依据，后续排查通过、驳回或投诉争议时缺少可追溯证据。

## 范围

### In Scope

- 商品审核通过或驳回时记录审核前商品核心字段快照。
- 商品审核完成后记录审核后字段快照、审核人、审核结果、备注、状态变化和审核时间。
- 商品详情接口返回最近的商品审核历史。
- 商品详情和审核弹窗展示当前提交值与最近一次审核后快照的差异。
- 初始化脚本和 AutoMigrate 补齐 `product_audit_logs` 表及快照字段。

### Out of Scope

- 不改造卖家端商品提交流程。
- 不新增独立的商品审核历史列表页。
- 不自动补写历史已审核商品的快照。
- 不改变商品审核角色权限和状态枚举。

## 页面与交互影响

- 受影响页面: 商品管理。
- 受影响路由: `/product`。
- 受影响布局或导航: 无。
- 受影响组件: 商品详情 Drawer、商品审核 Modal。
- 受影响交互状态: 有历史快照时展示差异；无历史快照时明确显示暂无历史快照。

## 接口与数据影响

- 受影响接口:
  - `GET /api/v1/products/:id`
  - `PUT /api/v1/products/:id/audit`
- 请求参数或响应结构变化:
  - 商品详情新增可选 `auditHistory`。
  - 审核请求参数不变。
- 受影响服务层: `frontend/src/services/api.ts`。
- 受影响状态管理: 无。
- 受影响后端 handler/service/repository: `backend/internal/handler`。
- 受影响数据库或缓存:
  - 新增或补齐 `product_audit_logs`。
  - 新增 `from_status`、`to_status`、`before_snapshot`、`after_snapshot` 字段。
- 配置或环境变量变化: 无。
- 构建或部署影响: 需要随 admin 后端发布执行 AutoMigrate；新库初始化脚本同步建表。

## 权限与合规影响

- 受影响角色: 超管、运营、审核员。
- 新增/调整权限: 无，继续复用商品审核 `RequireRole(1,2,3)`。
- 是否影响审核、风控、日志留痕: 是。商品审核会增加结构化历史快照，提升审核追溯能力。

## 验收标准

1. 商品审核通过或驳回后，`product_audit_logs` 写入审核人、结果、备注、状态变化和 before/after 快照。
2. 商品详情接口返回最近审核历史，前端能展示审核时间、审核人、结果、备注和状态变化。
3. 商品详情和审核弹窗能用最近一次审核后快照作为基准展示字段差异；无历史时显示暂无历史快照。
4. 既有商品审核请求参数、权限边界和状态枚举保持不变。
5. 后端测试、后端构建、前端测试和前端构建通过。
