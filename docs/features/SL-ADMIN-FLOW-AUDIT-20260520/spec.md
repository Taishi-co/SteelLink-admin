# SL-ADMIN-FLOW-AUDIT-20260520 Spec

## 基本信息

- Feature ID: `SL-ADMIN-FLOW-AUDIT-20260520`
- Feature 名称: 管理端审核决策与驳回理由校准
- 负责人: Codex
- 目标上线环境: staging / prod

## 背景

第三轮对照商品上架、企业入驻、服务能力和资源审核流程时，发现部分审核表单和后端校验仍存在决策风险：企业待审核记录打开弹窗时默认选中“驳回”，用户实名拒绝成功后前端详情会被误置为“已通过”，部分审核接口允许无驳回原因。审核类操作是主流程入口，错误默认值或缺少原因会影响业务方重新提交和平台留痕。

## 范围

### In Scope

- 修复企业待审核弹窗默认审核结果，待审和驳回记录默认走“通过/重新审核”路径。
- 用户实名审核成功后，前端按实际提交结果更新详情状态。
- 企业、商品、实名、服务能力申请、服务资源审核的驳回动作必须填写原因。
- 企业能力直接控制在驳回或暂停时必须填写原因。
- 后端审核接口只接受明确的通过/驳回状态，不允许回写待审核。
- 补齐审核状态校验单元测试。

### Out of Scope

- 不改造业务后端审核状态机。
- 不新增审核历史快照表。
- 不变更审核角色权限边界。
- 不自动修复历史无原因驳回数据。

## 页面与交互影响

- 受影响页面: 用户管理、企业审核、服务权限审核、服务资源审核、商品管理。
- 受影响路由: `/user`、`/enterprise`、`/enterprise/services`、`/service-offers/*`、`/product`。
- 受影响布局或导航: 无。
- 受影响组件: 审核 Modal、企业能力控制 Modal。
- 受影响交互状态: 驳回和暂停必须填写原因；已通过企业不再显示重复审核入口。

## 接口与数据影响

- 受影响接口:
  - `PUT /api/v1/users/:id/identity`
  - `PUT /api/v1/enterprises/:id/audit`
  - `PUT /api/v1/enterprise-service-applications/:id/audit`
  - `PUT /api/v1/enterprises/:id/services/:service/status`
  - `PUT /api/v1/products/:id/audit`
  - `PUT /api/v1/*-services/:id/audit`
- 请求参数或响应结构变化: 结构不变；非法状态或缺少驳回/暂停原因时返回 400。
- 受影响服务层: `frontend/src/services/api.ts` 的契约不变。
- 受影响状态管理: 用户详情本地状态更新修正。
- 受影响后端 handler/service/repository: `backend/internal/handler`。
- 受影响数据库或缓存: 无表结构变更。
- 配置或环境变量变化: 无。
- 构建或部署影响: 需要部署 admin 前后端。

## 权限与合规影响

- 受影响角色: 超管、运营、审核员。
- 新增/调整权限: 无。
- 是否影响审核、风控、日志留痕: 是，驳回原因成为必填，减少无法追溯的审核记录。

## 验收标准

1. 待审核企业打开审核弹窗默认选中“通过”，不会误默认“驳回”。
2. 已通过企业不显示重复审核按钮，已驳回企业可重新审核。
3. 用户实名驳回成功后，详情状态显示已驳回而不是已通过。
4. 后端审核接口收到待审核状态或非法状态时返回 400。
5. 所有驳回审核和企业能力暂停必须填写原因。
6. 前后端测试、构建和 harness gate 通过。
