# Feature Spec

## 基本信息

- Feature ID: `SL-ADMIN-GROUP-PROCUREMENT-BIDDING-V2`
- Feature 名称: 集采竞价 V2 管理端工作台
- 负责人: Codex
- 目标上线环境: staging

## 背景

当前管理端只支持围绕单一卖家商品发起集采、跟踪参团和结束成单，缺少“集采项目立项、供应商邀请、报价对比、手工定标”这几个核心运营动作，导致卖家竞价无法在平台内闭环。

本次改造需要把管理端升级为竞价集采工作台，支持平台运营围绕需求创建项目、邀请和审核供应商、查看报价、定标并最终生成订单。

## 范围

### In Scope

- 集采管理页升级为“项目 + 申请 + 供应商报价”三栏工作台。
- 支持从买家集采申请归并创建竞价项目。
- 支持邀请卖家、审核卖家报名、查看报价对比表、手工定标。
- 支持在项目已定标后执行成单。

### Out of Scope

- 电子合同与签章页面。
- AI 自动评标报告。
- 多供应商分标成单和复杂拆单。

## 页面与交互影响

- 受影响页面:
  - `frontend/src/pages/group-procurement/index.tsx`
- 受影响路由:
  - `/group-procurement`
- 受影响布局或导航:
  - 保持“集采管理”菜单不变
- 受影响组件:
  - 项目列表、申请列表、报价对比表、定标抽屉/弹窗
- 受影响交互状态:
  - 项目状态从“待卖家确认/参团中”升级为“归集中/报价中/已定标/已成单”

## 接口与数据影响

- 受影响接口:
  - 管理端 group procurement 相关接口重构为 project / enrollment / quote / award / order
- 请求参数或响应结构变化:
  - 创建项目需支持 `requestIds`、报名邀请、定标参数
  - 详情接口需返回报名、报价、中标信息
- 受影响服务层:
  - `frontend/src/services/*`
  - `backend/internal/handler/group_procurement.go`
- 受影响状态管理:
  - React Query key 需要按项目、报名、报价拆分
- 受影响后端 handler/service/repository:
  - 管理端 backend group procurement handler
- 受影响数据库或缓存:
  - 读取 backend 新增的项目/报名/报价表
- 配置或环境变量变化:
  - 无
- 构建或部署影响:
  - 无

## 权限与合规影响

- 受影响角色:
  - 平台运营/管理员
- 新增/调整权限:
  - 沿用现有集采管理权限
- 是否影响审核、风控、日志留痕:
  - 是，邀请、审核、定标、成单都需要留痕

## 验收标准

1. 管理端可从多个买家申请创建竞价项目，并邀请多个卖家参与。
2. 管理端可查看报名状态和报价对比表，并完成手工定标。
3. 定标后管理端可执行成单，页面可展示中标结果和订单结果。
