# Release Rules

## 目标

确保“准备上线”和“部署执行”是标准化、可复现、可回滚的同一套流程。

## 准备上线阶段必须完成

1. 执行 `./harness/release.sh docs/features/<feature-id>`
2. 完成 `release-checklist.md`
3. 确认环境变量、接口域名、代理、静态资源路径、前端构建产物、后端服务入口与部署入口
4. 明确 smoke test 范围与回滚点
5. 确认变更已通过 PR 合入 `main`

## 部署原则

- staging 与 production 统一走 `./harness/deploy.sh`
- 不允许直接在服务器、对象存储或 CDN 控制台中手工拼装部署步骤替代脚本
- 部署命令应与 CI 或发布平台调用方式保持一致
- 如项目尚未确定部署平台，至少通过 `DEPLOY_COMMAND` 明确唯一执行入口

## 上线前最少检查项

- 构建通过
- 已配置的前端 lint / typecheck / test 通过
- 后端测试与构建通过
- 接口域名、base path、路由模式与代理来源明确
- 登录页、首页、核心菜单、核心列表页 smoke 范围明确
- 关键后端接口、权限校验与依赖配置来源明确
- 环境变量与静态资源缓存策略有记录

## 上线后最少验证项

- 登录与退出流程可用
- 关键菜单与首页可访问
- 关键列表页、表单页可正常请求接口
- 权限控制与菜单可见性符合预期
- 关键后端健康检查、日志与依赖连接状态正常
- 静态资源加载、监控与控制台错误情况正常
